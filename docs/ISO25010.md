# ISO/IEC 25010 quality mapping

A conformance self-assessment against the ISO/IEC 25010 product-quality model
(the eight-characteristic 2011 model taught on the course; the 2023 revision
splits Safety out separately and renames some sub-characteristics, noted where
it changes the reading).

This is a claim about *this repository*, with evidence, not a certification.
Sub-characteristics that a two-process student game cannot meaningfully address
are marked "not applicable" with the reason rather than padded.

## 1. Functional suitability

| Sub-characteristic | Evidence |
|---|---|
| Completeness | Every mechanism in the specification is implemented and listed in [FEATURES.md](FEATURES.md): board and movement, barriers, scent, belief, commit-reveal, series, audit, reporting. |
| Correctness | The rules engine is deterministic Python with no network or LLM in the move path (`domain/__init__.py` states this as a rule). 1210 tests assert the rules; `domain/semantic_audit.py` re-derives the whole game from the log. |
| Appropriateness | `strategy/` is strictly downstream of `domain/` — the domain layer never imports strategy, so a bad policy can lose a game but cannot produce an illegal state (`strategy/brain.py:1`). |

## 2. Performance efficiency

| Sub-characteristic | Evidence |
|---|---|
| Time behaviour | Turn and watchdog timeouts are agreed terms, read from config (`sdk/agent_connection.py:81`); `peer/watchdog.py` bounds a stalled sub-game. |
| Resource utilisation | Token spend is metered and reported per series against `token_budget_per_series` (`shared/tokens.py`, [GATEKEEPER_AND_TOKENS.md](GATEKEEPER_AND_TOKENS.md)). |
| Capacity | `AdmissionQueue` (`shared/admission.py:36`) caps concurrency and queue depth; the inbound server has its own per-minute DoS limit (`infra/mcp_server.py`). |

## 3. Compatibility

| Sub-characteristic | Evidence |
|---|---|
| Co-existence | Police and Thief are separate repositories and separate OS processes sharing no memory (CLAUDE.md, spec ch. 2.4.2); `team_sync` talks to the sibling over its own MCP link, never in-process. |
| Interoperability | A signed, byte-identical `game.json` is the contract; the wire protocol, capture-claim echo and audit shape follow the cross-team league protocol ([P2P_PROTOCOL.md](P2P_PROTOCOL.md), [INTEROPERABILITY_AND_OPERATIONS.md](INTEROPERABILITY_AND_OPERATIONS.md)). Handshake negotiates dialect against a reply-dialect peer. |

## 4. Usability

| Sub-characteristic | Evidence |
|---|---|
| Learnability | [README.md](../README.md) is a user guide with install, run, replay and validation commands; `--help` covers every flag. |
| Operability | One CLI with opt-in flags (`--gui`, `--tunnel`, `--league`, `--replay`, `--export`, `--report`, `--count`). |
| User error protection | Config errors fail fast at start-up with a named cause (`exceptions.ConfigError`); league mode refuses to start on a misconfigured profile rather than producing an invalid match (`sdk/league.py`). |
| Recognisability / aesthetics | Live board and replay GUI with heatmap overlay (`gui/`, screenshots in [assets/](../assets)). |
| Accessibility | **Not addressed.** The Tk GUI has no screen-reader or contrast work; the CLI is the accessible path. Stated rather than claimed. |

## 5. Reliability

| Sub-characteristic | Evidence |
|---|---|
| Maturity | 1210 tests, 95.17% coverage (93% unomitted), zero Ruff violations. |
| Availability | The peer server binds independently of the opponent's liveness; a dead opponent is a typed `TransportError`, not a crash. |
| Fault tolerance | Bounded retry in the gatekeeper (`shared/gatekeeper_core.py:115`); the loop watchdog abandons a stalled sub-game; a crashed peer is scored as a technical loss by design, which is why `exceptions.py` separates deliberate errors from genuine bugs. |
| Recoverability | Series state is persisted and resumable (`team_sync/store.py`, `team_sync/resume.py`); every game is replayable from its production log (`sdk/replay.py`). |

## 6. Security

The strongest characteristic for this project, because the threat model is an
adversarial opponent rather than an outside attacker.

| Sub-characteristic | Evidence |
|---|---|
| Confidentiality | Partial observability is enforced structurally: the police never holds the thief's true position, only a posterior (`strategy/belief.py`). CLAUDE.md forbids sharing live state between the two agents. |
| Integrity | Commit-reveal binds each move before the opponent answers (`domain/crypto.py`); anti-replay and step-zero declaration seal the starting conditions. A tamper-forfeit zeroes both sides. |
| Non-repudiation | Terms are signed; `mutual_agreement.sha256` and `interop_sha256` are symmetric digests both peers can recompute (`report/result.py:65`). Verified byte-for-byte against the sibling thief repo *and* an independently written third implementation (`a613b6f`). |
| Accountability | Full production logs plus four mandatory JSON artifacts per series; the end-of-game semantic audit re-verifies every claim the opponent made (`domain/semantic_audit.py`). |
| Authenticity | Sibling `team_sync` messages are signed with a shared secret (`team_sync/security.py`). |

## 7. Maintainability

| Sub-characteristic | Evidence |
|---|---|
| Modularity | Nine packages with a stated dependency direction; the SDK is the only front-end boundary ([ARCHITECTURE.md](ARCHITECTURE.md)). |
| Reusability | AST scan finds zero duplicated function bodies of four or more statements; shared machinery lives in `shared/` precisely so the peer link, the LLM and the mailer share one rate limiter. |
| Analysability | Every module, class and public callable carries a docstring, and comments explain *why* rather than *what*. Max 150 non-blank/non-comment lines per file, enforced. |
| Modifiability | Six documented extension points ([EXTENSION_POINTS.md](EXTENSION_POINTS.md)); tunables are config keys, not literals. |
| Testability | The domain layer is pure and needs no network; `ThreatEstimate` is a `Protocol` so policies test against fakes; the GUI's non-widget half is deliberately Tk-free and headless-testable. |

## 8. Portability

| Sub-characteristic | Evidence |
|---|---|
| Adaptability | Pure Python 3.13, no compiled extensions. Windows Tk library paths are handled without hardcoding (`gui/__init__.py`). |
| Installability | `uv sync` from `pyproject.toml` + `uv.lock`; optional extras (`gmail`, `research`) keep the base install network-free. |
| Replaceability | The provider seam accepts any OpenAI-compatible endpoint (`infra/openai_compat.py`); the brain and threat model are swappable by config. |

## Gaps this assessment does not hide

1. No protocol state machine governs the match/turn lifecycle (Reliability → maturity);
   Appendix He rules 4 and 5 require one, and the sibling thief repo has it.
2. GUI accessibility (Usability) is unaddressed.
3. The tunnel is not a pluggable seam, so `--league` cannot be used with an externally managed tunnel (Portability → replaceability).
